## 2024-10-24 - Native Intl.DateTimeFormat Caching Performance
**Learning:** In React components mapped over lists (e.g. daily weather forecasts), using `moment(date).format(...)` inside the render function creates massive overhead. Benchmarks show that utilizing the native `Intl.DateTimeFormat` is ~78x faster. However, the real critical learning is that `Intl.DateTimeFormat` MUST be instantiated *outside* of the component (cached at module level). Re-instantiating it inside the React render cycle eliminates the performance gains due to its expensive initialization. Additionally, parsing `YYYY-MM-DD HH:mm:ss` (from OpenWeatherMap) with the native `Date` constructor causes cross-browser issues (Safari/iOS return NaN) unless hyphens are replaced with slashes (`.replace(/-/g, "/")`).
**Action:** When replacing `moment.js` with native Date formatting, always cache `Intl.DateTimeFormat` instances outside the component function and sanitize `-` to `/` in date strings before passing them to the `Date` constructor.
