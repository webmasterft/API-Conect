## 2024-03-24 - Cached Intl.DateTimeFormat instances over moment.js
**Learning:** Found a specific performance bottleneck where `moment.js` and standard `Intl.DateTimeFormat` instantiations were occurring on every render cycle of a mapped component (`cards.js`). Benchmarking confirms that caching `Intl.DateTimeFormat` instances outside of React components is significantly faster (orders of magnitude) than re-instantiating them during every render cycle or using `moment.js`, and also reduces bundle bloat.
**Action:** When parsing dates in React components, avoid importing heavy libraries like `moment.js` if standard `Intl.DateTimeFormat` will do. More importantly, always declare `Intl.DateTimeFormat` instances OUTSIDE the component function to avoid expensive re-instantiation during every render cycle, and remember to handle cross-browser compat (e.g. `.replace(/-/g, "/")`) when parsing date strings.
