## 2024-05-15 - [Intl.DateTimeFormat and Date parsing edge cases]
**Learning:** Heavy libraries like `moment.js` can be easily replaced with the native `Intl.DateTimeFormat` API for simpler date formatting needs. However, the `Intl.DateTimeFormat` object instantiation can be expensive. In React components, caching these instances outside of the component function prevents unnecessary re-instantiations on every render cycle. Additionally, native `Date` object parsing of ISO 8601-like formats (e.g. 'YYYY-MM-DD HH:mm:ss' from OpenWeatherMap) requires replacing hyphens with forward slashes (e.g., `dateString.replace(/-/g, "/")`) to avoid NaN errors and ensure cross-browser compatibility (particularly with Safari).
**Action:** When replacing date libraries with native alternatives in React, always define `Intl.DateTimeFormat` configurations outside the render scope. Always sanitize date strings containing hyphens to use slashes before utilizing the `Date` constructor, especially for data directly fetched from external APIs.
